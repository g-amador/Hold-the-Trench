## View zoom (+ / - keys, TWO views only)
- `+` (and `=`/KP_PLUS) zooms IN to config `VIEW_CLOSE`; `-` (KP_MINUS) zooms OUT to `VIEW_FULL`. Both set ABSOLUTE states (idempotent — no toggle flip-flop on key autorepeat) and work paused or live. Exactly these two views exist; no intermediate zoom steps.
- FULL = the whole battlefield via the uniform zoom (see Render layout); CLOSE = a player-centered window `CLOSE_VIEW_TILES` (13) tiles ACROSS, uniformly scaled so it OCCUPIES the whole visible strip (no bands): scale = SCREEN_WIDTH/(13*TILE_SIZE) ≈ 3.08x at 1280x768, ~98px screen tiles, ~7.4 tiles vertically, window vertically = visible_h/3.08 world px; camera clamped so the window never leaves the map. USER TWEAK (was 10 = 4x/128px/~5.7 tiles vertically, the original "at most ~5 squares in each direction" cap sample): the weaker zoom puts MORE native ground pixels under every screen px (≈1.4 src px per screen px instead of ~1.07) so the 4K art reads sharper — the trade-off accepted by the user is the wider ±6.5-tiles window.
- CLOSE GROUND QUALITY (user fix: "map is 4K but when I zoom in the quality is crap"): the CLOSE view samples its ground DIRECTLY from the NATIVE-resolution image (`TileMap.ground_texture_native`, e.g. the 5504x3072 map1_a/map1_c 4K art) instead of the pre-downscaled world-strip texture. `AssaultPhase.render` CLOSE path: skip the ground on the world surface (`TileMap.draw(..., skip_ground=True)`, only in SPRITES mode + native present), `TileMap.native_ground_rect(view_rect)` maps the 13-tile window to a proportional native crop (~2.2x more pixels per world px), smoothscale it to the strip (≈1.4 source pixels ≈ per screen pixel at the 3.08x zoom — downsampling, sharp), then blit the world surface's leftover content on top as a transparent ENTITY layer (world_surface is SRCALPHA; its window region is CLEARED every frame — without the ground blit nothing else overwrites it; stale pixels would become permanent ghosts). FULL view + BLOCKS mode + missing native file keep the classic single-pass path.
- CLOSE BUILDING HIRES (batch 7, user: "images zoom in or zoom out should have the same high quality"): every building ALSO holds `image_native` — the SAME art file at its TRUE resolution (loader helpers: `load_first_image_named` returns the winning filename alongside the world-size surface; the ctor re-loads it native-size via `load_image`, pre-flipped when is_enemy; statics load through `load_image_semi_alpha_fixed` and scale their world-sized art FROM the hardened native). In CLOSE SPRITES mode `AssaultPhase` skips native-owning buildings on the world surface (`TileMap.draw(..., skip_native_hires=True)` — checked per building, so missing-native kinds keep their low-res draw) and afterwards `_blit_building_hires` smoothscale-caches each native art ONCE per instance (`building._hires_cache`, target = footprint tiles × close_scale ≈ 4x screen px) and blits it straight onto the SCREEN (view-culled). Units are still 4x-upscaled world art in CLOSE (only buildings got the hires pass — user named buildings in their list). Since bunker proportionalization the hires target reads the building's `draw_size` (fallback = footprint) and blits at `draw_offset` × scale.
- HUD hint shows `+/-: view FULL|CLOSE` right after the pause info; each battle starts at FULL. Camera for CLOSE reads the LIVE player position every frame.

# PROPORTIONAL BUILDING ART (round 11, bunker scope; user: "dimensions of the bunkers vs how they are rendered — keep the image quality but proportional to what they must occupy")

- PROBLEM: bunker art files are LANDSCAPE cutaways with transparent margins (ger/opaque content ratio ~1.45–1.6 on a 1422x736 canvas; fr ~1.08–1.14 on 1201x880), but the renderer squeezed the FULL canvas into the square 6x6 (192x192) box → horizontally squashed in FULL and vertically stretched in CLOSE.
- FIX (applies to every scene variant a/b/c/d automatically — it keys off the winning file, not the variant letter):
  1. `utils/image_loader.opaque_bbox(filename, alpha_min=20, step=2, pad=8)` — samples the native art for the opaque content box (cached per filename in `_OPQ_BBOX_CACHE`, costs a few seconds ONCE per file per process on the venv's python-only loop; empty canvas falls back to the full canvas). NOTE: returns (left, top, RIGHT, BOTTOM) edges — never feed it straight to `pygame.Rect(box)` (Rect wants width/height; bunker.py builds `Rect(bx0, by0, bw, bh)` explicitly — the tuple-as-Rect bug distorted ratios AND crashed allies with "subsurface rectangle outside surface area").
